# استمرارية تحديث Paperclip العربي

هذا المستودع هو الفرع العربي الدائم من `paperclipai/paperclip`، وليس تعريبًا يُستبدل عند كل تحديث. التطبيق لا يستبدل ملفاته بملفات من GitHub الرسمي مباشرة لأن ذلك سيحذف التعريب وقد يعرّض البيانات لتغييرات غير متوافقة.

## البنية

1. `arabic-upstream-sync.yml`: يتحقق يوميًا من الفرع الرسمي `master`. يدمج التحديثات إلى الفرع العربي فقط إذا لم توجد تعارضات واجتازت اختبارات التعريب وTypeScript وVitest والبناء. عند الفشل يبقي الفرع السابق دون تغيير ويفتح Issue للمراجعة.
2. `arabic-windows-release.yml`: بعد تحديث الفرع العربي، يبني تطبيق Windows عربيًا من المصدر مع الخادم وقاعدة البيانات ضمن الحزمة، ويتحقق من الملفات، ثم ينشر نسخة جديدة في **GitHub Releases الخاص بالفرع العربي**.
   قبل نشر الإصدار، ينفّذ أيضًا اختبار تشغيل حقيقي للخادم وقاعدة البيانات باستخدام مجلد تجريبي معزول والتحقق من تقديم الواجهة العربية.
3. `desktop/launcher/update-watch.cjs` و`auto-update.cjs`: **تحديثات آلية بالكامل دون زر تنزيل أو نافذة تأكيد**. يفحص التطبيق الإصدارات الرسمية الخاصة بالنسخة العربية كل ساعة، وينزّل ملف NSIS الجديد تلقائيًا عبر `electron-updater` بعد التحقق من بيانات إصدار GitHub وملف `latest.yml` وبصمة SHA-512. ينشئ نسخة احتياطية ناجحة من PostgreSQL قبل السماح بالتثبيت. يثبّت الإصدار عند إغلاق التطبيق، أو يعيد التشغيل تلقائيًا عندما يكون جهاز المستخدم خاملًا مدة 30 دقيقة ولا توجد عمليات وكلاء قيد التنفيذ. إذا فشل النسخ الاحتياطي أو فحص بيانات الوكلاء يتوقف التثبيت ولا يمس البيانات.
4. `desktop/check-official-updates.ps1`: مراقب محلي للنسخة الرسمية عند إغلاق التطبيق؛ لا يغير الملفات. يُثبَّت اختياريًا عبر `desktop/enable-update-watch.ps1`.

في الجهاز الحالي، أُعيد بناء نسخة EXE عربية محدثة في `desktop/dist-next/win-unpacked/Paperclip Arabic.exe`، وجرى ربط اختصار `Paperclip Arabic` على سطح المكتب بهذا الملف. احتفظ بالمجلد `win-unpacked` كاملًا؛ يمكن الاستمرار في استخدام النسخة القديمة أثناء التشغيل، وتفعيل النسخة الجديدة عند الإغلاق وإعادة الفتح.

## الفرع العربي المستقل

أُنشئ **Fork** في حساب `amen78977` على GitHub، بعنوان `https://github.com/amen78977/paperclip`، مع بقاء `paperclipai/paperclip` مصدر التحديثات الرسمي. تُبنى التعديلات العربية في فرع Git محلي باسم `arabic-desktop`. يحدث استيراد التحديثات إلى `master` في Fork فقط، ولا نغير مشروع Paperclip الرسمي.

تعطلت مهام GitHub Actions الموروثة من المشروع الأصلي (23 مهمة) في Fork لتقليل الاستهلاك والتكاليف غير اللازمة. تُبقى فقط مهمتا التعريب والبناء مفعّلتين، مع محاولة تعطيل أي مهام أخرى تضيفها التحديثات الرسمية مستقبلًا.

تحتاج GitHub Actions إلى السماح بعمليات الكتابة إلى المستودع وفتح Issues؛ وإذا كانت معطلة في Fork فلا بد من تفعيلها قبل توقع تحديثات تعمل تلقائيًا. تنفَّذ المهام المجدولة من `master` في Fork.

تأكد من صفحة **Actions** في Fork أن مهمة `Arabic Desktop - upstream updates` تعمل وأن `Arabic Desktop - Windows release` تنجح، وأن إصدار GitHub يتضمن `Paperclip-Arabic-Setup-*.exe` و`latest.yml`. بعدها يصبح التحديث الآلي فاعلًا عند تثبيت إصدار يحتوي آلية `electron-updater` الجديدة **مرة واحدة**. الإصدارات القديمة التي لا تحتويها لا يمكنها تحديث نفسها بهذه الآلية، ويجب ترقيتها لمرة واحدة إلى الإصدار الذي يضمها. لا يتطلب أي إصدار لاحق تنزيلًا أو تثبيتًا يدويًا.

**تنبيه أمني:** مُثبّت Windows غير موقّع رقميًا حتى الآن. تحمي آلية التحديث سلامة تنزيل الملفات باستخدام التوقيعات التجزئية (SHA-512) من تغذية التحديثات الخاصة بالمستودع العربي، لكن ذلك **ليس بديلًا عن التوقيع الرقمي للناشر**؛ أي اختراق لصلاحيات نشر إصدارات GitHub يبقى خطرًا. لا نعتبر التوقيع الرقمي مكتملًا.

## التحقق المحلي

```powershell
node scripts/verify-arabic-continuity.mjs
node --test desktop/launcher/update-watch.test.cjs
node --test desktop/launcher/auto-update.test.cjs
powershell -NoProfile -File desktop/check-official-updates.ps1
powershell -NoProfile -File desktop/enable-update-watch.ps1
```

**قيود لازمة:** لا يمكن ضمان الدمج التلقائي لكل إصدار: تغييرات المنبع التي تتعارض مع التعريب أو تفشل الاختبارات تُوقَف. كما يلزم تقييم تغييرات قواعد البيانات والمكونات الأصلية قبل توزيعها. النسخة المحلية `win-unpacked` لا تستبدل نفسها تلقائيًا، وملف `Setup.exe` القديم ليس أحدث بناء بعد.

- نُقل إصلاح نسخ روابط OpenCode إلى مرحلة تغليف خادم npm أيضًا، وأضيف اختبار فعلي للـ junctions وعزل ملفات المستخدم وحفظ الموافقات، مع بوابة تحقق تمنع شحنه دون الإصلاح.
- طُبّق التحديث المحلي من ملفات الحزمة المفكوكة المتحقَّق منها إلى مسار التثبيت السابق، بعد نسخة كاملة لملفات البرنامج ونسخة بيانات أثناء توقف الخادم ونسخة SQL رسمية. نسخة التطبيق `0.1.27` والخادم `2026.1023.0`. بقي سجل إزالة تثبيت Windows السابق كما هو؛ لا ندّعي اجتياز تثبيت NSIS جديد.
- أُوقفت محاولتا ضغط مثبت NSIS الطويلتان ولم يُنشر مثبت أو إصدار GitHub جديد. يظل التحقق من مثبت جديد وجهاز نظيف غير منجز؛ استخدام الملفات المفكوكة لا يثبت ذلك.
